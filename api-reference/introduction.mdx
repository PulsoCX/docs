The Pulso API exposes a single public endpoint: `POST /v1/conversations`. It accepts a `pulsoVersionId`, a `channel`, and the channel-specific destination, and returns the freshly created conversation. Everything else (identity, the conversational AI, the analysis pipeline, action execution, notifications) happens inside the platform; the integrator only needs to trigger it.

## Base URL

```
https://api.pulso.cx
```

## Authentication

Every request requires an API key issued from the Pulso console, sent as a Bearer token:

```
Authorization: Bearer pk_live_...
```

Keys are scoped per tenant. The endpoint documented here requires the `conversations:write` scope. Missing or expired keys produce `401 UNAUTHORIZED`; keys without the right scope produce `403 FORBIDDEN`.

## Errors

Errors follow a stable shape:

```json
{
  "statusCode": 422,
  "code": "VALIDATION_ERROR",
  "message": "channel=whatsapp requires channelMetadata.phoneE164 in E.164 format",
  "timestamp": "2026-05-15T07:03:25.264Z",
  "path": "/v1/conversations"
}
```

Use `code` for control flow; `message` is human-oriented and may change between releases.

| Status | Code               | Meaning                                                                 |
| ------ | ------------------ | ----------------------------------------------------------------------- |
| 401    | `UNAUTHORIZED`     | Bearer token is missing, malformed, or revoked.                         |
| 403    | `FORBIDDEN`        | The API key is valid but lacks the required scope.                      |
| 404    | `NOT_FOUND`        | The `pulsoVersionId` does not exist or belongs to a different tenant.   |
| 422    | `VALIDATION_ERROR` | The body failed schema validation (missing `phoneE164`, wrong channel). |
| 5xx    | `INTERNAL_ERROR`   | Transient platform error; safe to retry with backoff.                   |

## Idempotency

`POST /v1/conversations` is not idempotent at the request level: a retry with the same body creates a fresh conversation. Idempotency is enforced one layer down (the action plan and individual action executions are deduplicated by natural keys), so the integrator should not retry the trigger on transient network errors unless creating duplicate conversations is acceptable.
